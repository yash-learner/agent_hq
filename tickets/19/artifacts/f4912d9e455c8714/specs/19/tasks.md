## Task 1: Extend care.config.ts to parse REACT_NAV_LINKS

**Repo:** yash-learner/care_fe_agent_hq  
**Dependencies:** None  
**Estimated LOC:** ~80 lines

### Description
Add environment variable parsing for `REACT_NAV_LINKS` to support custom navigation links. This task establishes the configuration layer that will be consumed by the navigation components.

### Changes Required
- Parse `REACT_NAV_LINKS` JSON string from environment
- Validate structure (array of objects with required `name` and `url` fields)
- Add error handling for invalid JSON with console logging
- Export `customNavLinks` property from `careConfig`
- Define TypeScript interface for custom link shape matching `NavigationLink`

### Implementation Details
```typescript
// Expected interface (matching NavigationLink from nav-main.tsx)
interface CustomNavLink {
  name: string;
  url: string;
  icon?: { type: "care" | "lucide"; icon: string };
  target?: string;
  visibility?: boolean;
  children?: CustomNavLink[];
}

// Parse with error handling:
const customNavLinks: CustomNavLink[] = (() => {
  const raw = env.REACT_NAV_LINKS;
  if (!raw) return [];
  
  try {
    const parsed = JSON.parse(raw);
    if (!Array.isArray(parsed)) {
      console.error("REACT_NAV_LINKS must be a JSON array");
      return [];
    }
    
    // Validate required fields
    const valid = parsed.every(
      (link) => typeof link === "object" && link.name && link.url
    );
    if (!valid) {
      console.error("REACT_NAV_LINKS: Each link requires 'name' and 'url'");
      return [];
    }
    
    return parsed;
  } catch (err) {
    console.error("REACT_NAV_LINKS parse error:", err);
    return [];
  }
})();
```

### Testing
- Valid JSON with multiple links parses correctly
- Invalid JSON logs error and returns empty array
- Missing required fields logs error and returns empty array
- Empty or undefined env var returns empty array without error

### Acceptance Criteria Coverage
- **AC7**: Invalid JSON logs console error, app continues without custom links

## Task 2: Inject custom links into facility navigation

**Repo:** yash-learner/care_fe_agent_hq  
**Dependencies:** Task 1 (requires `careConfig.customNavLinks`)  
**Estimated LOC:** ~120 lines

### Description
Modify `src/components/ui/sidebar/facility/facility-nav.tsx` to inject custom links from `careConfig.customNavLinks` into the facility navigation. This task integrates the configuration layer with the navigation rendering.

### Changes Required
- Import `careConfig.customNavLinks`
- Transform custom links to match `NavigationLink` interface used by `NavMain`
- Implement icon resolution logic for CareIcon and Lucide icons
- Inject custom links into navigation array generated by `generateFacilityLinks()`
- Position custom links after built-in links and plugin links
- Support `target="_blank"` for external links
- Support `visibility: false` to hide links conditionally

### Implementation Details
```typescript
// Icon resolution helper
const resolveCustomLinkIcon = (icon?: { type: "care" | "lucide"; icon: string }) => {
  if (!icon) return undefined;
  
  if (icon.type === "care") {
    return <CareIcon icon={icon.icon as any} />;
  }
  
  if (icon.type === "lucide") {
    // Dynamically import Lucide icon
    const LucideIcon = lucideIcons[icon.icon];
    return LucideIcon ? <LucideIcon className="size-4" /> : undefined;
  }
  
  return undefined;
};

// Transform custom links
const customLinks = careConfig.customNavLinks.map((link) => ({
  name: link.name,
  url: link.url,
  icon: resolveCustomLinkIcon(link.icon),
  target: link.target,
  visibility: link.visibility ?? true,
  children: link.children?.map((child) => ({
    name: child.name,
    url: child.url,
    icon: resolveCustomLinkIcon(child.icon),
    target: child.target,
    visibility: child.visibility ?? true,
  })),
}));

// In generateFacilityLinks():
return [
  ...builtInLinks,
  ...pluginNavItems,
  ...customLinks,
];
```

### Integration Points
- Existing plugin link injection via `pluginNavItems` from `useCareApps()`
- Existing `NavMain` component handles tooltip display when collapsed
- Existing visibility filtering in `NavMain`

### Testing
- Custom links render after built-in and plugin links
- Links with `target="_blank"` open in new tab
- Links with icons display specified CareIcon or Lucide icon
- Links with `visibility: false` do not render
- Links without icons show default Avatar with first letter
- Sidebar collapse shows tooltip on hover (existing behavior)

### Acceptance Criteria Coverage
- **AC1**: Custom links from `REACT_NAV_LINKS` render in navbar alongside existing navigation
- **AC2**: Links with `target="_blank"` open in new tab
- **AC3**: Links with `icon` display specified CareIcon or Lucide icon
- **AC4**: Links with `visibility: false` do not appear

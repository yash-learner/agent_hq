# QA Plan: Show app version in login page footer

## AC1 — Version displays on login page without authentication

### Research map

- routes: `/login` is public, no authentication required
- components: `src/components/Auth/AuthHero.tsx` (footer section, lines 99-125)
- hooks: `src/hooks/useAppVersion.ts` provides `versionInfo` with `version` field
- version source: `/public/build-meta.json` (generated via `npm run build:meta`)
- auth/role: none (public page)
- permissions / facility-scoped: no (public page)
- fixtures needed: none (version is build metadata, not fixture data)

### Prerequisites

- None (public page, no authentication required)
- Dev server running at `http://localhost:4000` or production build via `npm run preview`

### Data setup

- Not applicable: version is sourced from build metadata (`/build-meta.json`), not user data
- Build metadata generated via `npm run build:meta` (creates UUID version in `public/build-meta.json`)
- For local dev: metadata is already generated by setup; dev server fetches it via `useAppVersion` hook
- Version format: UUID string (e.g., `2d3eeed0-38da-46bf-ad98-34e565be02fd`)

### Steps

1. **Action:** Open browser and navigate to `http://localhost:4000/login` (or `/login` on the preview server if testing production build)
   **Expect:** Login page loads, showing the CARE hero section on the left with the footer at the bottom
   **Record through:** yes

2. **Action:** Scroll to the bottom of the left hero section and locate the footer with "Contribute on GitHub | Third Party Software Licenses" links
   **Expect:** Footer displays with the existing GitHub and licenses links, followed by a pipe separator `|` and the version text in the format `v{uuid}` (e.g., `v2d3eeed0-38da-46bf-ad98-34e565be02fd`)
   **Record through:** yes

3. **Action:** Inspect the version text styling
   **Expect:** Version text is smaller than the link text (text-xs class) and styled in a muted secondary color (text-secondary-500), making it visually distinct from the clickable links
   **Record through:** yes

### Success looks like

- Version text visible in footer after GitHub and licenses links
- Version format: `v{uuid}` where uuid is the build identifier
- Text is small and muted (not distracting from main content)
- No authentication required to see the version

## Test plan / notes

### Manual testing approach

- Test in both dev server (`npm run dev`) and production build (`npm run build && npm run preview`)
- Verify version appears in both environments (dev fetches from `/build-meta.json`, production includes it in build)
- Test responsive behavior: mobile viewports may wrap footer content differently (not a blocker, AC2 specifies desktop only)

### Browser compatibility

- Test in Chrome/Edge (primary), Firefox, Safari
- Verify version text renders consistently across browsers

### Build verification

- Run `npm run build:meta` to ensure `build-meta.json` is generated with valid UUID
- Verify `useAppVersion` hook fetches version without errors (check browser console)
- If version doesn't appear, check: build-meta.json exists, contains valid version field, no React Query errors

### Edge cases

- First visit (no stored version): should still display current version
- Version fetch failure: version won't display (graceful degradation via conditional render)
- Long UUID: should not break layout due to inline-flex and text-xs sizing

### Playwright E2E coverage (not live QA criteria)

- Consider adding E2E test to verify version renders on `/login` page
- Test selector: `.text-secondary-500` containing version text pattern `/^v[0-9a-f-]{36}$/`
- Verify footer link navigation still works after version addition

# Review: Save Purchase Delivery item with Shift + Enter

## Round 1

- **blocker** `src/pages/Facility/services/inventory/externalSupply/deliveryOrder/AddSupplyDeliveryForm.tsx:618-627` — onKeyDown handler prevents Enter from submitting but doesn't move focus to the next field. AC1-4 explicitly require "focus moves to the next field" when Enter is pressed. The current implementation only calls `e.preventDefault()` which stops submission but leaves focus in place. Need to either programmatically move focus with `.focus()` on the next input, or simulate Tab behavior. Browser's native Enter behavior doesn't move focus between fields.

The plan provides a 12-step UI recipe to create a delivery order but doesn't cite existing test fixtures, facility IDs from `tests/setup/*.ts`, or API paths from `src/types/inventory/**/*Api.ts`. Compare against `src/types/inventory/supplyDelivery/supplyDeliveryApi.ts` (lines 11-55) for API structure and `src/types/inventory/deliveryOrder/deliveryOrderApi.ts` for delivery order creation paths. No test in `tests/` covers supply delivery flow, so either reference the backend fixture IDs (`load_fixtures` command output) or provide API calls with proven request bodies from the form schemas in `AddSupplyDeliveryForm.tsx` (lines 80-150) and `SmartExternalDeliveryRow.tsx`.
